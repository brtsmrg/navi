Navi: where it runs, and how we keep it running

Short answer: Navi needs very few servers. The app lives on the phone. We rent a little static storage, one tiny licence service and one small router machine. Everything else is borrowed, free or cheap.

How to read the badges: checked read on a vendor page on 25 Nov 2026. varies sources disagree. not checked from general knowledge, check before relying on it.

1. Today: what Navi leans on

Navi is a web app saved on the phone. It has no server of its own. Each time it needs a route, a place name or a road shape, it asks a free public service.

The big risk is Overpass. checked Its public servers are meant for light use, around 10,000 questions a day counted across all users of an app, and commercial apps are asked to run their own or pay. Paying customers should not depend on it.

varies GitHub Pages is also meant for sites, not for running a business. Check their current terms before charging money from it. Moving the app to Cloudflare Pages is a one-day job.

2. The plan: rent as little as possible

Three rented things. Everything static (app, maps, road packs, voice files) sits on cheap storage with a global cache. One tiny service handles licences. One small machine does routing.

Why this shape

  • Static files are nearly free. checked Cloudflare R2 charges nothing for downloads. Storage is 10 GB free, then $0.015 per GB a month.
  • Maps in one file. checked The PMTiles format is a single file on plain storage that the phone reads in small pieces. A city or region is about 100 MB; the whole planet is roughly 60 to 120 GB depending on the build.
  • Licences are tiny. checked Workers are free for 100,000 requests a day, then $0.30 per million. D1 gives 5 GB free.
  • Only routing needs a real machine. It is the one piece that cannot be a static file.

3. What happens on a drive

The goal: after the first setup, a ride works with no signal. Servers are only touched at the edges.

The 14 day grace period in step 4 is a design choice, not a measured number. Pick it with the Pro offer.

6. Where the money goes

You set $49 a year, and $125 lifetime in a launch window. Stores take a cut. A web card checkout takes less but only works where the app is allowed to send people to the web.

  • checked Apple's Small Business Program lowers the commission to 15% for developers earning under $1 million a year. You must enrol.
  • checked Google Play charges 15% on auto-renewing subscriptions from day one.
  • not checked Whether the iPhone app may link to web checkout, and RevenueCat pricing, need a look at the current Apple rules and their price page before building billing.
  • not checked Sales tax and VAT on digital sales. Stores collect it for in-app sales. A web checkout needs a provider that handles it.

7. Build order

Stage 0 · Now

  • Ship the Plain English call style and the bend sketch.
  • Keep retry and fallback on Overpass so a bad mirror does not stop a route.
  • Write the Pro offer page and a waitlist form. No payments yet.

Stage 1 · Before launch

  • Get a domain name. Put the app on Cloudflare Pages.
  • Start the small router server. Test it with real rally stages.
  • Build the nightly road packs for your first countries. Store on R2. App reads them first and uses Overpass only as backup.
  • Copy the voice model to R2.
  • Add uptime pings and error reports.

Stage 2 · Launch

  • Licence service and little database.
  • Store billing on iPhone and Android, card checkout on the web.
  • Privacy page and terms, read by a lawyer. You are in Canada, so PIPEDA applies, plus GDPR if you sell to Europe.
  • Credit OpenStreetMap on screen and in the store listing. Its licence requires it.
  • Nightly backup of the database to a second place.

Stage 3 · Growth

  • Convoy: group ride location sharing with live connections. Needs a design pass and a cost check first.
  • Cloud sync of saved routes.
  • Second router machine in another region.
  • CarPlay and Android Auto. Apple and Google both gate this behind approval and the wait is not checked.

9. Keeping it safe

  • HTTPS only. The licence service accepts only requests signed by the stores or the payment provider.
  • Secret keys live in the host's secret store. Never in the app, never in the repo.
  • The router server: only the Cloudflare address can reach it. Login by key, no passwords.
  • Collect as little as possible: a licence id and a receipt. No location history on our side.
  • Rate limits on every public address, so one bad actor cannot run up the bill.
  • Not enforced today: the page security headers file does not apply on GitHub Pages. Cloudflare Pages does apply it, so moving fixes this too.
